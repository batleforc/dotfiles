# Batleforc's Dotfiles

This repository contains my personal dotfiles and configuration files for various applications and tools that I use on my systems. Keep in mind that most of these configurations are tailored to be used with [Chezmoi](https://chezmoi.io/), a popular dotfile management tool and my atomic OS [Weebo-os](https://github.com/batleforc/weebo-os).

## Contents

- **Shell Configurations**: Custom configurations for Bash, Starship, and other tools.
- **Editor Configurations**:
  - Neovim settings is moved to it's [dedicated repo](https://github.com/batleforc/weebo-dotfiles-nvim) - will be used in Eclipse Che
  - Configurations for VSCode.

## How the files are owned

Some apps rewrite their own config, so the repo does not always own the whole file:

- **`modify_` scripts** pin only the keys the repo cares about and keep the rest:
  DMS `settings.json` (theme, animations, idle/lock timeouts) and VS Code
  `settings.json` (portable keys from `settings.portable.jsonc`; machine-local
  ones like kubeconfig paths stay on the machine).
- **`create_` files** are seeds: chezmoi writes them once, then the app owns them
  (`niri/dms/*.kdl`, regenerated by DMS).
- `~/.config/DankMaterialShell` is a compatibility symlink to `~/.config/dms`
  and is ignored on purpose.

## VS Code extensions

`dot_config/Code/User/extensions.json` lists the extensions chezmoi installs (the
`run_onchange_` script re-runs when the list changes). Extensions that another
one pulls in (the Markdown pack, Remote-SSH helpers) are left out on purpose.

Two are not on the Marketplace and must be installed by hand from their VSIX:
`batlehub.batlehub-theme` (the BatleHub colour theme) and `batlehub.che-remote-ssh`.

## Theme

BatleHub everywhere: VS Code (extension), DMS (`dms/themes/batlehub`), niri
(`niri/batlehub.kdl`), Ghostty (`ghostty/themes/batlehub`) and Starship. Crimson
is the action colour, copper means pending, amber is for focus only, and the
ground is true black for OLED panels.

## Checks

`scripts/check.sh` renders the repo into a throwaway home and validates it
(niri, shellcheck, JSON/JSONC, fontconfig, the `modify_` scripts, Ghostty when
installed). CI runs it in `fedora:44` on every push.

## Fonts

`recipes/base/common-modules.yml`), not from these dotfiles.
